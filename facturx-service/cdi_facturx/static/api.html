INTÉGRATION BACKOFFICE

Une facture. Une requête.

Envoyez le PDF et ses données structurées. Le service ne retourne un fichier qu’après validation complète.

1. Lire le PDF et obtenir son empreinte

POST /api/facturx/import-pdf
Content-Type: multipart/form-data
pdf : fichier PDF (20 Mo maximum)

Réponse : source_sha256, candidates, text, warnings. Les propositions d’extraction sont à vérifier.

2. Générer le Factur-X

POST /api/facturx/generate?output=json
Content-Type: multipart/form-data
pdf : le même fichier PDF
payload : objet JSON sérialisé

{
  "profile": "en16931",
  "source_sha256": "empreinte SHA-256 obtenue à l’import",
  "reviewed": true,
  "invoice": { ... }
}

Utilisez examples/demonstration.json comme exemple complet de l’objet invoice. Le schéma OpenAPI décrit les entrées multipart ; la définition exacte des données métier figure dans cdi_facturx/models.py et dans ce schéma JSON.

output=json : rapport, PDF base64, XML et rapport veraPDF. output=pdf : PDF binaire. output=zip : PDF + XML + rapports.

Réponses

  • 200 : tous les contrôles bloquants ont passé.
  • 422 : données ou document invalides, détails dans errors.
  • 503 : validateur indisponible ou capacité atteinte, aucun PDF.
  • 401 / 403 : clé API, origine ou hôte refusés.
  • 413 : fichier ou requête trop volumineux.

Déploiement

Le lanceur écoute sur 127.0.0.1. Pour le backoffice, privilégiez un appel serveur à serveur vers le service privé. Configurez FACTURX_API_KEY, envoyez X-API-Key et limitez les hôtes avec FACTURX_ALLOWED_HOSTS. Ne placez pas la clé dans du JavaScript public.

Les versions, les dépendances système et les limites fonctionnelles sont détaillées dans le README livré avec le code.
